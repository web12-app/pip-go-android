# Pip-Go Android Runtime

The installed runtime client — the "Expo Go" of the Pip-Go ecosystem.
Loads, displays and hot-reloads plain React bundles served by `pip-go dev`.

> **One-time setup** — the Android app is independent from your React projects.
> Install it once, then point it at any Pip-Go dev server.

## Build

```bash
# 1. Open in Android Studio (Koala+ / AGP 8.2 recommended) → Run ▶
# or
# 2. Command line:
./gradlew assembleDebug          # output: app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Requirements: JDK 17, Android SDK 34. The Gradle wrapper JAR is generated by
Android Studio on first sync (or run `gradle wrapper --gradle-version 8.5`).

## Connecting to a dev server

On your development machine:

```bash
pip-go dev
# → prints the Network URL (http://<lan-ip>:3000) and a QR code
```

On the device (same Wi-Fi network — no tunnel, no tokens):

1. **Scan QR** — point the camera at the QR shown in the terminal
2. **Discover** — picks up the `_pipgo._tcp.` mDNS advertisement
3. **Manual** — type `http://192.168.1.20:3000`

## Architecture

```
MainActivity (Compose)
 ├─ ConnectScreen ─ QR / mDNS / manual → RuntimeManager.connect(url)
 ├─ PreviewScreen ─ AndroidView(RuntimeWebView) + status chip + viewport footer
 └─ ErrorScreen   ─ Retry / Reload

RuntimeManager (state machine: StateFlow<RuntimeState>)
 ├─ DevConnection (OkHttp WS)  → reload / fast-refresh / build-error messages
 ├─ BundleCache (§21)          → last-good bundle for offline fallback
 ├─ RuntimeWebViewFactory      → WebView + WebViewAssetLoader + console relay
 ├─ PipGoBridge                → window.PipGoBridge (approved APIs)
 └─ NativeViewHost             → native child WebViews for <View src>
```

## Notes

- `usesCleartextTraffic="true"` is required for plain-HTTP dev servers.
- Fast Refresh is executed **in-page** by the host page glue (see
  `pip-go-cli/src/hostpage.ts`); the native WS client handles `reload`
  messages and status chrome.
- The offline fallback host page is generated by `RuntimeWebViewFactory` and
  served through `WebViewAssetLoader` from the bundle cache.
